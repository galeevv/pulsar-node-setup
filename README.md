# Мастер установки Remnawave-ноды

Установщик для **нового VPS с Ubuntu 24.04**. Подготавливает сервер, Docker, firewall, сертификат/nginx и remnanode. Работает с любой панелью Remnawave: IP панели и Secret Key вводит владелец. Профиль Xray, Node, Host и сквод создаются отдельно в панели.

## Обычная установка — одна команда, один проход

Подключитесь по SSH **к новому VPS**, выполните `sudo -i`, затем:

```bash
curl -fsSL https://raw.githubusercontent.com/galeevv/pulsar-node-setup/main/new-node.sh -o /root/new-node.sh
bash /root/new-node.sh
```

Мастер последовательно попросит:

1. **Тип подключения** из меню ниже.
2. **IPv4 панели**, которой разрешается подключаться к порту управления нодой.
3. **Домен ноды**. Для CDN отдельно спросит origin-домен и CDN-домен, путь и loopback-порт.
4. **Secret Key** из инструкции установки ноды в вашей панели. Вставьте только значение одной строкой и нажмите Enter. Ввод скрыт: символы не появятся на экране. Это не API token и не Reality privateKey.
5. Подтверждение плана. После него мастер установит необходимые компоненты и покажет дальнейшие шаги в панели.

**Останавливаться, вручную создавать .env и перезапускать скрипт ради ключа больше не нужно.** Никаких ключей и адресов конкретного владельца в установщике нет.

Если это первая нода, заранее откройте в панели инструкцию установки ноды и скопируйте Secret Key. Если ноды уже есть, используйте ключ этой же панели. Не вызывайте операции генерации/ротации ключей только ради установки.

## Какой тип выбрать

| Пункт | Тип | Кто занимает 443 | Что подготовить |
| --- | --- | --- | --- |
| 1 | `reality` | Xray, RAW Reality | Адрес/домен ноды; подходящий SNI target |
| 2 | `selfsteal` | Xray, XHTTP Reality | Домен с A-записью на VPS; nginx-сайт работает на 127.0.0.1:8443 |
| 3 | `cdn` | nginx → Xray на 127.0.0.1:4444 | Origin-домен с A-записью, отдельный CDN-домен и CDN-ресурс |
| 4 | `hysteria` | Xray, UDP 443 | Домен с A-записью и TLS-сертификат |

Для CDN настройте HTTPS до origin, корректный Host origin-домена, отключите кэширование и сжатие туннеля. Поддержка GET uplink и способ передачи данных зависят от вашего CDN и версии Xray: установщик их не угадывает и профиль транспорта не подменяет. Размер отдельного заголовка nginx ограничен 32 KiB; лимиты CDN и Xray проверяются отдельно.

Для `selfsteal` готовый пример будет **XHTTP Reality**, а не RAW. Установщик не преобразует существующую RAW-ноду: миграция действующей ноды требует отдельного плана.

## Посмотреть план

```bash
bash new-node.sh --plan --yes --type selfsteal \
  --domain node.example.com --panel-ip 192.0.2.10
```

`--plan` не устанавливает пакеты, не меняет конфиги, не делает сетевых проверок и не читает Secret Key. Работает без root. Без `--yes` недостающие параметры спрашиваются через терминал.

## Повторный запуск и ошибка установки

Запустите ту же команду или `bash /root/new-node.sh`. Мастер подхватит параметры из `/opt/pulsar-node-setup/settings.tsv` и ключ из `/opt/remnanode/.env`. Повторный запуск повторяет проверки и этапы установки; это не транзакционный откат всей ОС.

- Сохранённые Secret Key и Reality-ключи не меняются сами.
- Свой `index.html` сохраняется.
- UFW не сбрасывается; старые правила сохраняются. Уже существующее широкое правило на порт управления нужно проверить вручную.
- Docker daemon.json не переписывается, весь Docker не перезапускается.
- Полное обновление ОС выполняется только с `--upgrade-packages`.
- Nginx проверяется перед reload; при ошибке проверки возвращается предыдущий файл virtual host.
- Смена типа или домена сохранённой установки и импорт ноды старого установщика блокируются, чтобы не перезаписать рабочую конфигурацию.

При ошибке выводится этап. Исправьте причину и повторите запуск. Например, при неправильной A-записи Secret Key уже будет сохранён и снова вводить его не придётся.

## Автоматизация и флаги

Для интерактивной установки достаточно скрытого ввода. Для автоматической — подготовьте на VPS файл, доступный только root, содержащий **только значение ключа**, и передайте путь:

```bash
chmod 600 /root/node-secret.txt
bash new-node.sh --yes --type cdn \
  --panel-ip 192.0.2.10 --domain origin.example.com --cdn-domain cdn.example.com \
  --secret-key-file /root/node-secret.txt
```

Не передавайте ключ аргументом командной строки и не добавляйте его в Git. После успешной установки исходный файл можно удалить: рабочая копия находится в `/opt/remnanode/.env`, режим 600.

| Флаг | Значение |
| --- | --- |
| `--type` | reality / selfsteal / cdn / hysteria |
| `--panel-ip` | IPv4 панели, без CIDR |
| `--domain` | Домен без схемы, порта и пути |
| `--cdn-domain` | Клиентский домен CDN |
| `--path` | Путь XHTTP; должен совпасть с профилем и Host |
| `--port` | Loopback Xray для CDN, по умолчанию 4444 |
| `--node-port` | Управление нодой, по умолчанию 2222 |
| `--sni` | Внешний Reality target для типа reality; иначе подбор с ноды |
| `--node-image` | Образ remnawave/node; для воспроизводимости укажите версию или digest |
| `--mem-limit` | Лимит памяти, например 1500m; по умолчанию 75% RAM |
| `--secret-key-file` | Файл с Secret Key; заменяет сохранённое значение |
| `--upgrade-packages` | Дополнительно выполнить apt upgrade |
| `--harden` | Отключить вход по паролю; сначала проверьте отдельный вход по ключу |
| `--yes` | Без вопросов; обязательные значения должны быть заданы/сохранены |
| `--plan` | Только план без изменений |

Без терминала и без `--yes` установка не считает отсутствие ответа согласием.

## Что сделать в панели после установки

1. Создать Config Profile с inbound нужного типа. Для Reality пример с ключом находится **на VPS** в `/opt/pulsar-node-setup/panel-reality.txt` (root only), не печатается в обычном выводе установщика. Откройте файл по SSH и перенесите inbound в профиль. Secret Key ноды и Reality privateKey — разные ключи.
2. Создать Node: IP VPS, порт управления; выбрать профиль и активный inbound.
3. Создать Host: клиентский адрес, порт, TLS/Reality, SNI и XHTTP-параметры должны соответствовать профилю. Для CDN клиент подключается к CDN-домену, для selfsteal — к домену ноды.
4. Добавить inbound сначала в тестовый сквод и выдать тестовому пользователю.
5. Проверить подписку и **реальный трафик с клиента**, затем выдавать рабочему скводу.

`/health` проверяет nginx, открытый порт управления — remnanode. Это ещё не проверка VPN. Успешный подбор SNI с VPS тоже не подтверждает его доступность из сети клиента.

## SSH-доступ

Если ключ SSH ещё не установлен, из консоли провайдера или первоначального подключения:

```bash
bash bootstrap-node-access.sh --key "ssh-ed25519 AAAA... ваш-публичный-ключ"
```

Сначала проверьте вход в новой SSH-сессии. Только затем используйте `--harden`.

## Проверки разработчика

```bash
bash -n new-node.sh
bash tests/test-installer.sh
python3 tests/test-secret-prompt.py
# Требует nginx и openssl; запускает только изолированный nginx на loopback:
sudo python3 tests/test-nginx.py
```

Тесты выполняются на Linux в временном каталоге: четыре режима плана, валидация ввода, отказ без подтверждения, чтение/повторное использование ключа, сохранение дополнительных env-полей и параметров. Они не запускают установку на хосте.

Nginx: [буферизация proxy](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering), [лимиты заголовков](https://nginx.org/en/docs/http/ngx_http_core_module.html#large_client_header_buffers).

Полная установка на чистой Ubuntu (apt, Docker, UFW, ACME) не покрыта этими тестами; проверяйте релиз на отдельном тестовом VPS перед массовым использованием.

## CDN: готовые настройки upload

Режим CDN использует проверенную на польской ноде схему Yandex CDN:
`packet-up`, GET без тела, данные в заголовках `stream-*`.
Пакет ограничен 24 000 байтами, отдельный заголовок — 3 000 байтами;
интервал отправок — 10 мс, лимит заголовков Xray — 65 536 байт.
Nginx получает `large_client_header_buffers 4 16k`; буферизация и кэш
туннеля отключены. Это исправляет несогласованные лимиты, но не гарантирует
одинаковую скорость на всех CDN и клиентских сетях.

После установки откройте `/opt/pulsar-node-setup/panel-cdn.txt` на VPS.
Установщик создаёт:
- `panel-cdn-inbound.json` — объект для массива `inbounds` профиля;
- `panel-cdn-host-extra.json` — содержимое поля **XHTTP Extra Params** в Host.

Домены, путь и порт берутся из ваших ответов мастеру. Перенесите **оба** JSON:
изменение только профиля не ограничивает пакеты клиента. Затем обновите
подписку, переподключитесь и проверьте отправку файла. Скрипт не меняет панель.
Параметры проверены с Xray 26.7.28; клиенту нужна поддержка GET/header XHTTP.
Secret Key по-прежнему вводится скрыто; чужих ключей и доменов в шаблонах нет.
Это шаблон новых нод, а не команда массового обновления существующих.
